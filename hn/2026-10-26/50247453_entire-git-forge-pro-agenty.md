**Entire staví Git forge pro spolupráci agentů a lidí**

Hacker News · lizziepika · 26. října 2026, 18:23 · 55 bodů / 35 komentářů · [diskuse](https://news.ycombinator.com/item?id=50247453)

Startup Entire, který vede Thomas Dohmke, představil první Git forge navržený specificky pro spolupráci lidských vývojářů a AI agentů. Oznámení na blogu firmy popisuje tři nové stavební kameny, které mají nahradit klasický pull request. Služba je ode dneška dostupná každému vývojáři, mířit má ale hlavně na týmy, kde většinu kódu píší agenti.

Místo pull requestu nabízí Trail, přehled ve stylu pilotního kokpitu, kde na každý push bodují kód nezávislí revizní agenti v podobě automatických evaluací. Distribuovaný hosting kompatibilní s Gitem má zvládat pushe až 89krát rychleji než GitHub a šestkrát rychleji než Cursor Origin a repozitáře umí replikovat mezi USA, EU, Austrálií a Indií. Takzvaná Continuous Memory pak přes nástroje entire-graph a entire-brain ukládá relace a prompty agentů přímo do repozitáře, aby byly trvale dostupné a prohledatelné. Prvnotřídní integrace pro průběžnou integraci zajišťují partneři Buildkite a Depot, jejichž výsledky se na Trailu ukazují jako kontrola blokující merge.

Nejživější debata se vede o samotné tezi, že pull request už není správnou jednotkou revize. Uživatel aboreddev píše, že zajímavé není hostování, ale právě toto tvrzení, a souhlasí s ním: diff je levný, zatímco zdůvodnění zmizí ve chvíli, kdy se zavře session, a za šest týdnů při hledání chyby zbude jen zpráva, kterou si agent napsal sám pro sebe. Uložení session ke commitu mu proto připadá jako rozumná odpověď, i když pochybuje, že to někdo otevře při běžné revizi a ne až při incidentu. Do vlákna vstoupil i rkarthik1993, který se představil jako technický ředitel Entire pro terén, a nabídl, že vysvětlí mechaniku: jak se session vážou na commity přes git refs, co číslo o 89násobku znamená a neznamená nebo kdo může číst cizí přepisy.

Odtud se diskuse stočila ke skepsi, zda více artefaktů znamená lepší přehled. Uživatel argee se ptá, jestli by před érou jazykových modelů dávala smysl tříhodinová nahrávka obrazovky vývojáře přiložená k diffu, když pull request je syntézou úsilí a procházet nahrávky by stálo víc námahy. Správná cesta je podle něj usilovat o méně, ale dostatečných artefaktů, a pokud agenti píší většinu kódu, klade otázku, proč by firma vůbec trvala na lidské revizi místo smyčky agentů napojených rovnou na podporu. Uživatel 0gs k tomu dodává praktičtější pochybnost, proč by měl svá proprietární data pro agenty ukládat zrovna u Entire, když kontext jde držet kdekoli, a zda jedinou mrkví je úspora času pro velké organizace.

Třetí linka řeší provedení a cenu. Uživatel stryan chválí generátor grafu kódu, ale zbytek postu označuje za úmorný marketing, kvůli kterému se k dobrým kouskům jen těžko prokousává, a pohled Trailů by si dobrovolně nevybral. Uživatel shepherdjerred píše, že o ceně nenašel nic a vyzkoušel by to, kdyby věděl, že účet bude rozumný, na což Haimantika z týmu Entire odpovídá, že se platí jen za agenty a na start je kredit 100 dolarů. Uživatel conartist6 pak celou premisu, že lidé už většinu kódu nepíší, odmítá jako víru a ptá se, zda Entire nesází cynicky na to, že špatné programátorské nástroje nepůjdou nikdy opravit. Uživatel infogulch to celé rámuje jako součást širšího pohybu ve správě zdrojáků od DeltaDB přes Git 3.0 a Scion až po Cursor Origin a Radicle.

Z vlákna tak zůstává pocit, že Entire trefil skutečný problém mizejícího zdůvodnění agenturního kódu, ale komunita zatím váhá, zda odpovědí má být další vrstva hodnocení, paměti a hostingu.
