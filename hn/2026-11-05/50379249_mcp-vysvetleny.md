**MCP vysvětlený: jak AI aplikace mluví s nástroji**

Hacker News · rwilinski · 5. listopadu 2026, 15:08 · 279 bodů / 118 komentářů · [diskuse](https://news.ycombinator.com/item?id=50379249)

Na webu mcp-explained.com vznikl interaktivní průvodce protokolem Model Context Protocol, který má na animacích a krátkých lekcích ukázat, jak si aplikace umělé inteligence říkají o nástroje a data. Stránka láká na rychlý start i na skoky rovnou k nástrojům, stroji času specifikace a kapitole o lámání bezpečnosti.

Samotný web popisuje MCP jako otevřený standard pro propojení AI aplikací s nástroji a daty: server oznámí, co umí, aplikace to ukáže modelu a když model něco chce, aplikace zavolá server a výsledek mu předá zpět. Rozlišuje přitom tři role – hosta, tedy aplikaci jako Claude, Cursor, ChatGPT či nějakého agenta, server vystavující nástroje, data nebo prompty, a model, který o použití rozhoduje, ale se serverem nikdy nemluví přímo. Lekce pak pokrývají nástroje, zdroje a prompty, síťový tok zpráv i takzvaný stroj času specifikace a část o otravování serverů a dalších útocích.

Nejživější přestřelka se strhla kolem toho, jestli je výklad příliš hustý a co vlastně MCP je. Uživatel nater5000 napsal, že je to celé zbytečně hutné a že jde v podstatě jen o REST API se standardizovanými endpointy pro objevování, na což dingaling911 opáčil, že je to doslova JSON-RPC a s REST nemá nic společného. Aurornis dodal, že úvod má jeden odstavec a pět položek tabulky včetně výrazného „Není REST", a přesto se právě pod ním objevilo zavádějící přirovnání k REST. WhitneyLand naopak ocenil úsporný styl psaní a tipoval, že text nepsalo syrové LLM bez kurátora, zatímco jrmg poznamenal, že takové vysvětlovače dávají smysl hlavně těm, kdo systém už znají, protože nováčkům mlčky předpokládají jeho tvar.

Do toho se ozvala linka o „AI slopu". Uživatel ddellacosta označil stránku za hlučný brak, který nic nevysvětluje, a volal po jedné definici a jednom diagramu ve stylu Edwarda Tufteho. Brazukadev to přisoudil lidem bez průpravy v UX, kteří mají dobrý nápad, nechají ho vygenerovat umělou inteligencí a nepoznají, že výsledek je nestravitelný, a drop_star si posteskl, že podobný AI dashboard tu přistane každý den. Uživatel flyingsky k tomu přidal hlubší úvahu o vzdělávání vývojářů: když se dnes chce něco naučit, zeptá se Clauda, staví si znalosti postupně a nechává si iterativně stavět animace, takže statické interaktivní stránky ztrácejí část někdejší hodnoty.

Třetí proud diskuse řešil, jestli jsou MCP servery vůbec potřeba, když existují dobrá rozhraní příkazové řádky. Shaolinspirit nadhodil, že dobrá CLI jsou obvykle lepší, a ByteOfWood si stěžoval na nekomponovatelnost: jeho agent musí přes MCP pro Bluebeam převalovat velké objemy dat v tokenech tam a zpět, zatímco s CLI by je jen rouroval, takže si nakonec kolem MCP napsal obálku, aby ho mohl používat jako CLI. Naopak tedivm připomněl, že dát nedůvěryhodným agentům přístup do shellu by kvůli prompt injection znamenalo riskovat převzetí systému, a právě pro bezpečné vystavení vybraných nástrojů má MCP smysl. Podobně toddmorey radil začít od solidního HTTP API a CLI a MCP přidat až podle potřeby, zatímco Atiscant popsal, že obalení API do MCP s omezenými volbami a rozumnými výchozími hodnotami šetří tokeny a krotí slabší modely i limity API.

Závěr vlákna patřil otázce skládání volání. Ndriscoll se ptal, jestli v Codexu dokáže model zřetězit třeba volání Jiry do grepu, sedu nebo souboru, nebo jestli je MCP jen horší variantou curlu a popisků. Uživatel zzbzq odpověděl, že pořádně to stále neumí a že dovednost říkající klientovi, aby volal CLI a postupně si četla nápovědu, vychází v testech lépe, i když časem možná bude záležet stále méně, protože modely tak rychle sílí. Cefboud a kbdiaz kontrovali poukazem na CodeMode v Opencode a Pi, kde agent skládá nástroje a MCP právě psaním kódu, a dingaling911 doplnil, že harness Pi to při přesném zadání typu najdi nejnovější produkční tikety z Jiry a analyzuj související logy zvládne v pohodě.

Celkově tak diskuse ukazuje MCP jako užitečnou, ale spornou vrstvu mezi modelem a světem: pro někoho zbytečnou nadstavbu nad API a CLI, pro jiného způsob, jak agentům bezpečně a úsporně dávkovat nástroje.
